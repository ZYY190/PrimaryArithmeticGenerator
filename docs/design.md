# 设计实现说明

## 需求到模块的映射

| 需求 | 实现位置 | 处理方式 |
| --- | --- | --- |
| `-n`、`-r` 参数 | `CliOptions`、`Main` | 解析并校验正整数，`-r` 未提供时显示帮助 |
| 自然数、分数、带分数 | `Fraction`、`ExpressionParser` | 分数自动约分，带分数转换成分数 |
| 不超过 3 个运算符 | `ArithmeticGenerator` | 随机生成 1 至 3 个二叉运算节点 |
| 减法不为负 | `ArithmeticGenerator.constrain` | 若左值小于右值，交换左右子树 |
| 除法结果为正真分数 | `ArithmeticGenerator.constrain` | 保证左值大于 0 且小于右值 |
| 题目不重复 | `Expression.canonicalKey` | 对加法和乘法递归排序子树，再生成规范化键 |
| 输出文件和答案文件 | `FileService` | 使用 UTF-8 写入 `Exercises.txt` 与 `Answers.txt` |
| 1 万道题 | `ArithmeticGenerator`、`TestRunner` | 使用集合和表达式树，测试实际生成 10,000 道 |
| 答案判分 | `Grader`、`ExpressionParser` | 解析题目和答案，比较约分后的分数 |

## 类与职责

| 类或接口 | 职责 |
| --- | --- |
| `Main` | 命令行入口，协调生成或判分流程 |
| `CliOptions` | 解析 `-n`、`-r`、`-e`、`-a`、`-h` |
| `Fraction` | 不可变分数，负责约分、四则运算、比较和格式化 |
| `Operator` | 运算符、优先级、交换性和计算函数 |
| `Expression` | 表达式接口，包含数字节点和二元运算节点 |
| `ArithmeticGenerator` | 生成满足约束且不重复的表达式 |
| `ExpressionParser` | 递归下降解析器，支持分数、带分数和括号 |
| `Question` | 题号、表达式和标准答案 |
| `FileService` | 题目、答案和判分结果的写文件逻辑 |
| `Grader` | 逐行判分并统计正确与错误题号 |
| `PerformanceRunner` | 单规模性能测试 |
| `BenchmarkSuite` | 多规模性能测试 |
| `ProfilingRunner` | 线程栈采样热点分析 |

## 核心算法

### 分数模型

`Fraction` 使用 `BigInteger` 保存分子和分母。每次运算后使用最大公约数约分，并保证分母为正。这样可以避免浮点误差，也能支持较大的自然数范围。显示分数时，结果小于 1 时输出 `a/b`，结果大于 1 时输出 `w’a/b`。

### 表达式规范化

表达式使用二叉树表示。每个节点生成规范化键：

- 数字节点使用约分后的 `分子/分母`。
- 减法节点保留左、右子树顺序。
- 除法节点保留左、右子树顺序。
- 加法节点递归生成左右键后，按键排序。
- 乘法节点递归生成左右键后，按键排序。

因此 `a + b` 与 `b + a`、`a × b` 与 `b × a` 会被判为重复；`1 + 2 + 3` 与 `3 + (2 + 1)` 也会得到相同键；而 `1 + 2 + 3` 与 `3 + 2 + 1` 的二叉树结构不同，会保留为两道题。

### 生成约束

生成器先随机选择运算符数量，再递归生成左右子树。对于减法和除法，在父节点计算完成后检查中间值：

- 减法：若 `left < right`，交换左右子树。
- 除法：若右值为 0、左值为 0或左右相等，则本次生成失败并重试；若左值大于右值，则交换，最终保证结果为正真分数。

每成功生成一个表达式后，使用规范化键加入 `HashSet`，重复则继续尝试。

### 复杂度

每道题的运算符不超过 3 个，因此单题表达式树节点最多 7 个。规范化需要访问每个节点一次，单题复杂度为 `O(1)`；生成 `n` 道题的期望复杂度为 `O(n)`，额外空间用于保存题目和规范化键集合。
